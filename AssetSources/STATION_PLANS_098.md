`StationPlans/coverage.json`은 모든 역 ID에 대해 일치·누락 호선과 계획역 여부를 기록한다. 1,103개 ID 중 25개는 계획 노선만 갖는다. 계획역의 완공 실내 도면이 있다고 추정하지 않는다.

역명은 괄호 부역명, 공백, 끝의 ‘역’만 정규화했다. 지역·호선이 다른 동명역이나 비슷한 이름을 임의로 합치지 않는다. 최신 자료 기준일을 우선하며 동일 기준일의 서로 다른 층은 전부 보존한다. 각 매칭 결과의 `sourceIds`, `sourceDate`, `sourceURL`, `planURL`로 출처를 확인할 수 있다.

## 게임에서 사용하는 방법

새 파일 `Assets/Scripts/StationPlanData.cs`의 `StationPlanData.ForStation(station,line)`은 해당 역·호선의 `Entry`를 반환한다. 등록된 실제 위치에서 이동된 역, 사용자 생성 역·노선, 계획 노선은 `null`을 반환한다.

- `platformType`, `platformLength`: 기존 서울교통공사 건축 CSV에 호선·역명이 일치할 때만 채워진다. 그 외에는 빈 문자열과 0이다.
- `platformFloors`: 공식 승강장 자료에 쓰인 층을 모두 보존한다. 음수는 지하, 양수는 지상 층 표기이다.
- `HasSingleFloor`, `hasPlatformFloor`: 원문 층 값이 하나일 때만 참이다. 정확성 검증을 뜻하지 않는다. 여러 층이 나오면 `platformFloor=0`이고 전체 층 배열을 사용한다.
- `platformFloorLabel`: B4 / B3와 같은 출처의 층 표기이다. 원본 표시이며 그대로 확정 안내에 사용하면 안 된다.
- `HasDiagram`, `planURL`: 해당 역·호선의 안내도가 대조되었는지와 공식 링크이다. 서울·코레일은 공식 자료 다운로드 페이지, 부산은 해당 안내도 링크이다.
- `planCount`는 도면 이미지 개수이다. 같은 역의 여러 장을 별개의 역사로 세면 안 된다.

자료는 최초 사용 시 한 번 읽고 역 ID·호선 ID로 즉시 조회한다. 수백 MB의 원본 안내도를 플레이 중 로딩하지 않는다.

## 직접 확인한 안내도 예

`StationPlans/cache/plans/seoul/2호선/222 강남역.jpg`에서 2호선 B1 대합실·B2 상대식 승강장, 신분당선 B1/B3 대합실·B4 승강장, 1~12번 출구와 층간 연결을 확인했다. 이 안내도는 층별 연결 구조를 검토할 근거지만 통로 길이·너비·천장고·절대 깊이를 측량한 CAD가 아니다.

김포공항 9호선·공항철도 CSV는 승강장 층이 B3/B4로 여러 개 나온다. 이를 하나의 층으로 강제하지 않는다. 김포공항 상세 출구·실내 배치는 사용자가 첨부한 안내도와 해당 역 공식 안내도, 기존 전용 모델을 함께 대조해야 한다.

## 남은 한계

이번 작업은 공공 안내도와 층·승강장 자료의 수집, 모든 게임 역 ID 대조, 런타임 조회 기능이다. 모든 안내도를 사람이 한 장씩 검토하거나 실내 형상을 재작성한 것은 아니다.

공식 CSV에도 복수 층·다른 자료와의 불일치가 있다. 문산 1~4F는 안내도로 확인한 1F와 충돌하며, 신길 1호선처럼 원문 층이 한 값이어도 잘못된 사례가 있다. 원본과 검증값을 분리했다. 일부 대경선의 지상·지하 혼재는 대조가 남아 있다. 층 번호를 임의의 층고로 곱해서 실제 깊이로 주장해서는 안 된다. `HasSingleFloor`는 데이터가 한 값이라는 뜻이며 현장 실측 정확도를 보증하지 않는다.

남은 208개 ID는 일반철도·KTX 전용 역, 신림선·김포골드라인·GTX 일부, 미개통 계획역, 명칭이 정확히 일치하지 않는 일부 역 등을 포함한다. 전국 모든 역의 공개 CAD, 모든 출구 좌표, 통로 폭·천장고·절대 깊이를 확보한 상태가 아니다. 공통 모델이나 추정 치수를 정밀복원 완료로 표시하지 않는다.

## 재현 및 검증

`StationPlans/acquire.py`는 공개 데이터포털 다운로드 절차로 CSV 원본을 수집한다. `acquire_busan.py`는 공식 역 코드 목록과 각 역 안내도 링크로 이미지를 수집한다. `import_plans.py`는 원본 파일 및 현재 게임 역 목록에서 메타데이터와 대조 결과를 재생성한다. `validate.py`는 파일 해시·이미지 형식·ID 매칭·중복·층 분기·원본 출처 참조를 검사한다.

Unity 실행·게임 화면 검증은 이 자료 수집 작업에서 실행하지 않았다.

### 런타임 안전장치와 참조 화면

- `platformFloors`, `platformFloorLabel`, `platformFloor`: 기존 CSV 원본값. 검증값으로 덮어쓰지 않는다.
- `verifiedPlatformFloors`, `verifiedPlatformFloorLabel`: 안내도의 명시적인 승강장 층을 직접 읽어 확인한 값만 기록.
- `floorQuality`: `published-unreviewed`, `review-required`, `source-conflict`, `diagram-reviewed`, `multi-level-reviewed`, `missing` 중 하나.
- `floorQualityNote`, `floorEvidenceURL`: 충돌 내용과 실제 확인한 공식 안내도 출처.
- **화면에서는 `FloorReferenceLabel`을 사용한다.** 검증된 층과 대조 전 CSV를 구분하며, 충돌에는 `(CSV와 불일치)`를 붙인다. 기존 `hasPlatformFloor` 조건만 사용하면 문산처럼 충돌한 복수 층 역이 아예 표시되지 않는다.
- `HasVerifiedFloor`는 안내도 층 대조 여부이며 실측 치수 확인이 아니다.
- `floorGeometryAllowed`는 모든 행에서 `false`, `CanUseFloorForGeometry`도 항상 `false`. 층 이름만으로 절대 깊이·층고·통로 형상을 계산하지 않는다.
- `reviewedPlatformType`은 직접 대조된 형태. 강남 2호선은 건축 CSV도 안내도도 `상대식`이다. **현행 `WorldBuilder.Station.cs`의 강남 섬식 모델은 실제와 다르다.** 자료 수집 작업에서 다른 담당자의 역사 생성 코드·보행 경로는 수정하지 않았다.
