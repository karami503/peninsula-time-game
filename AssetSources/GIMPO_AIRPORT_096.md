# 김포공항 국내선 실내 동선 · 0.9.6

조사일: 2026-10-08. 한국공항공사 공개 이용객 안내 자료를 열어 층별 용도와 주요 연결 관계를 확인했다.

## 반영한 사실과 재구성 범위

| 항목 | 반영 |
|---|---|
| 1층 | 도착장·수하물 찾는 곳·교통 안내·서쪽 지하철 연결 방향 |
| 2층 | 항공사 체크인, 셀프 체크인, 출발 정보 |
| 3층 | 두 출발장 진입 구역과 보안검색, 긴 좌우 탑승동 |
| 4층 | 식당가와 전망 방향 |
| 수직 이동 | 1→2층, 2→3층, 3→4층의 계단실을 뚫고 실제 걸을 수 있는 계단 경사면과 양옆 난간 설치 |
| 탑승 | 탑승구 안내 데스크 옆 → 탑승교 → 항공기 측면 문 → 기내 통로 → 첫 열 좌석에서 출발 |

공식 이용객 안내도는 실측 CAD가 아니며, 게임의 실내 좌표·층고 6m·본관 120×60m·탑승동 길이 300m·계단 길이·탑승교 경사는 **플레이 가능한 재구성 치수**다. 실제 김포공항 전체 설계도와 일치한다고 주장하지 않는다. 공식 3층 도면의 중앙 돌출 탑승동과 전체 실제 탑승구 배열은 그대로 복제하지 않았으며, 기존 게임의 8개 가상 항공편과 8개 게이트를 유지한다. 상점·카운터 배치, 객실 좌석 수와 항공기 내부도 게임용이다. 공항 실내는 기존 별도 공간 `AirportOrigin=(550,0,0)`을 유지한다. 바깥 공항/역의 지도 위치와 실내 로컬 치수를 혼동하면 안 된다.

## 수정 사항

- 기존 1층→2층 계단 생성 호출이 없어 실제로 위층에 갈 수 없던 결함을 복원했다.
- 기존 2층 보안검색을 공식 안내와 같은 3층으로 옮겼다. 2층→3층 계단은 검색대 이전의 일반 구역이다.
- 바닥은 계단실 구멍을 제외한 직사각형 조각으로 생성하며, 표지·난간을 진입부/도착부에서 치운다.
- 마중 난간 중앙에 6m 보행 여유를 남겼다. 탑승구 출입문 위치의 유리벽과 수직 프레임도 제거했다.
- 탑승교에 실제 바닥 충돌면, 측벽, 천장, 조명을 넣고 높이 3m의 항공기 전방 출입구에 연결했다. 끝의 수직 막음벽과 오른쪽 난간이 정면 이탈을 막고, 왼쪽 기내 진입부는 열어 두었다. 안내판은 머리 위에 수직으로 배치했다.
- 원본 FBX는 변경하지 않고 인스턴스 메시를 잘라 문을 냈다. 기내 바닥·좌석·통로를 항공기 자식으로 만들어 비행 시 함께 움직인다.
- 긴 탑승동에는 서로 반대 방향의 무빙워크를 24m씩 분리 배치했다. 게이트로 꺾는 지점은 비워 둔다.
- 기내 좌석의 `gate` 상호작용으로 기존 이륙/도착 게임 흐름을 실행한다. 비행 중 조종/객실 자유 보행은 기존 비행 연출과 다른 기능이며 이번에 추가하지 않았다.

## 통합 계약

- 지하철과 연결하는 청사 서쪽 구멍: `AirportOrigin + (-60,0,-16)` 유지. 폭 2.5m, 높이 3.1m.
- `AirportSecuritySpawn`: `AirportOrigin + (-10.5,13.65,-4)` (카메라 눈높이 포함).
- `AirportBoardingDoor(gate)`: 항공기 문 앞 바닥 위치. 탑승구 안내 데스크가 아니라 기내 첫 열 좌석에 기존 `gate` 기능이 있다.
- `GameController.Transit` 통합 완료: 보안검색 바로가기 3층, 발권 문구에서 3층으로 올라가 검색하는 순서, `BoardAtGate`의 `securityPassed` 조건.
- `AirportModelImport`가 항공기 FBX의 Read/Write를 켠다. 새 메시 생성에 필요하며 런타임에서 원본 에셋 파일을 쓰지 않는다.

## 검증

`PeninsulaTime.AirportAccessCheck.Run`을 Unity Editor 배치 모드에서 실행한다. 확인 대상:

1. 세 층간 계단의 양쪽 6개 경로를 일반 플레이어 충돌·중력 이동으로 왕복.
2. 실제 지하철 연결 문에서 3층 검색대까지 연속 보행.
3. 8개 탑승교와 8개 기내 진입 경로를 왕복.
4. 보안검색을 통과한 위치에서 1번 항공기 좌석까지 연속 보행.
5. 보안검색 4개 통로가 모두 3층, 출발 상호작용 8개가 실제 항공기 내부에 있는지 확인.
6. 항공기 1번·8번의 인스턴스 메시에 출입문이 실제 생성되었는지 확인.
7. 8개 탑승교에서 중앙·좌·우 3개 위치마다 앞으로 계속 걷는 24회 시험: 끝 막음벽에서 멈춰 발판 위에 남는지, 이후 뒤로 걸어 나와 왼쪽 기내로 들어갈 수 있는지 검사.

최종 통합 뒤 Unity AirportAccessCheck를 통과했다. macOS 실행본에서 층간 계단 보행, 체크인, 3층 보안검색, 6번 탑승교 끝 추락 방지와 기내 진입, 첫 열 좌석 출발을 직접 확인했다. HB 1219 대구행의 활주로 주행과 비행 완료 후 대구 도착 화면도 확인했다. Windows·Android는 빌드 성공 확인이며 기기 플레이 검증은 하지 않았다.

사용자가 첨부한 AD 차트와 같은 종류의 공식 자료를 직접 확인했다.

- [국토교통부 항공정보관리체계 RKSS AD 2, 2026-01-08 판](https://aim.koca.go.kr/eaipPub/Package/2026-01-08/html/eAIP/KR-AD-2.RKSS-en-GB.html)
- [공식 RKSS AD CHART 2-1 PDF, 2026-01-08](https://aim.koca.go.kr/eaipPub/Package/2026-01-08/pdf/AD/RKSS/%282-1%29%20AD%20CHART.pdf)

PDF를 `work/096/RKSS-AD-CHART-2026-01-08.pdf`에 저장하고 첫 페이지를 렌더링해 육안 확인했다. 이 확인 판본을 사용했으며, 최신 운항용 차트임을 보증하는 자료가 아니다.

### 검증된 제원

| 활주로 | 실제 길이×폭 | 실제 진방위 |
|---|---|---|
| 14L / 32R | 3,600 × 45m | 약 135.01° / 315.03° |
| 14R / 32L | 3,200 × 60m | 약 135.00° / 315.02° |

AD 2.12의 시단 좌표 차이에서 평행 활주로 간 횡방향 간격은 약 360m, 두 14 방향 시단의 종방향 차이는 약 6m로 계산된다. 이 두 수치는 좌표를 평면으로 근사한 계산값이다. 차트의 평행 배치, 시단·중앙선·조준점·측선 표시, P 평행 유도로와 곡선 연결 형태를 반영했다. AD 2.8에 따라 P는 30m, G2는 40m, A와 주요 연결 유도로는 35m 폭을 사용한다.

### 게임상 가정과 변경

- 기존 단일 1,200m 활주로를 위 실제 제원의 평행 활주로 두 개로 교체했다.
- 실내 별도 공간과 게이트를 유지하기 위해 **공항 로컬 +X를 14 방향, -X를 32 방향**으로 대응시켰다. 지리 좌표에 맞게 전체 청사를 회전시킨 것은 아니다.
- 가까운 활주로는 **14R/32L (3,200×60m)**, 중심은 기존 `RunwayZ=322.5`이다. 먼 활주로는 **14L/32R (3,600×45m)**로 여기에 360m를 더했다. +X를 바라볼 때 +Z가 왼쪽이라는 기준을 적용했고, 14R 시단은 14L보다 진행 방향으로 6m 앞에 있다. 청사와 활주로의 거리, 계류장 범위, 유도로별 교차 위치·곡률은 게임용 재구성이다. 도면의 모든 주기장·격납고·시설·유도로를 복제하지 않았다.
- 도시 타일 위로 비행장 바닥이 겹치던 문제를 수정했다. 청사·8개 게이트의 위치를 유지하고 **활주로와 연결 유도로 구역을 로컬 +X 방향으로 2,400m 이동**했다. 가까운 활주로 시단은 로컬 X=606m, 먼 시단은 600m이며, 이 배치는 실측 위치가 아닌 별도 플레이 공간 구성이다. 계류장의 사용하지 않는 서쪽 부분을 잘라 기존 650m 도시 타일 밖에 두었다.
- 8개 항공기는 기존 게이트에서 후진한 뒤 동쪽으로 꺾어 화면에 그려진 곡선 유도선을 따라 P → G2 방향으로 이동하고, 가까운 14R 방향으로 정렬한 뒤 이륙한다. 지상 이륙 가속 거리는 1,350m로 이 짧은 활주로의 끝 이전에 뜨도록 유지했다. 택싱과 비행 시간은 **66초로 압축한 게임 연출**이며 실제 운항 속도나 관제 절차 재현이 아니다.
- 기존 `PlaneFlight` 경로를 지정하지 않는 호출은 이전 24초 연출을 유지한다. 실제 탑승은 `ConfigureAirportFlight`가 새 경로를 전달한다.
- 청사·역·게이트 스폰·기내 보행 경로는 변경하지 않았다. 비행장 지면과 유도로는 이 별도 공간 안에서 연속적으로 연결했다.

### 외부 비행장 검증 진입점

`PeninsulaTime.WorldBuilder.RunAirfieldCheck`는 슬래시가 포함된 활주로 이름을 정확히 검색한 뒤 실제 생성한 메시 위에 테스트용 충돌면을 붙이고 두 활주로의 크기·간격·진행 방향 기준 좌우와 시단 차이, 모든 8개 게이트의 후진/유도로/이륙 위치가 노면 위에 있는지, 이륙 가속 마지막 시점까지 가까운 14R 활주로 위에 있는지, 이륙 방향과 비행 완료 여부를 검사한다. 모든 비행장 노면이 도시 타일 동쪽에 있는지, 가장 가까운 지면이 실제 비행장 노면인지, 위에 다른 도시 건물이 가리는지도 검사한다. 긴 유도로 삼각형은 100m 이하의 구간으로 분할했다. 최종 Unity AirfieldCheck와 macOS·Windows·Android 빌드를 통과했다. macOS 실행본에서 지정된 좌석 탑승 뒤 활주로 주행과 대구 도착을 확인했다. 검사 로그와 직접 플레이 이미지를 0.9.6 전달물에 포함했다.
